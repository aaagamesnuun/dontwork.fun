# dontworkの思想と設計方針

dontworkは、架空のお金で「元手を作る → 組み合わせる → 結果を見る → 次を考える」を楽しむゲームです。短い操作の手応えと、組み合わせが育っていく面白さを大切にします。この文書は共同開発の判断軸です。現在の具体的な設定は[LABガイド](LAB.md)、実装の境界は[設計ガイド](ARCHITECTURE.md)を参照してください。

## 1. 小さな操作から、大きな変化が生まれる

WORKで元手を作り、ポジションと強化に投資し、AUTOでその結果を眺めます。序盤の一押しも、後半の大きな配当も、何が起きたか分かることが大切です。

操作量だけを増やす変更よりも、選択の意味が増える変更を歓迎します。強化が便利になったかを考えるときは、価格だけでなく、買えるまでの体験、購入後の変化、次の目標の分かりやすさを見ます。すべての設定を安くすればよい、速くすればよい、とは考えません。

## 2. 同じ出目を、違う組み合わせで楽しむ

メインのスピンは1〜100の**共通の出目**で全ポジションを精算します。各ポジションに別々の乱数を与えるゲームではありません。同時に当たる組み合わせ、逆方向の動きをする組み合わせ、条件を育てる組み合わせが、構成を考える面白さにつながります。

配当、賭け金、勝率、期待値、条件の記憶を説明できる状態に保ちます。見た目だけを変えたつもりで、この共通抽選や会計を変えないでください。Coin Flipなど独立した遊びは、メイン抽選との区別を保ちます。

## 3. 派手でも、起きたことが読める

お金の雨、光、振動、音、チャートは、結果を感じるための演出です。大きな勝ちには大きな手応えが欲しい一方で、現在の資産、操作ボタン、次にできることが埋もれると遊びにくくなります。

演出の長さとゲームの精算を分け、結果が見える前に勝ち金や解放情報が漏れないようにします。演出中もWORKや許可された購入が反応することを守ります。スマホの発熱や操作遅延、狭い画面、ミュートや動きを抑える設定も、演出の品質に含めて考えます。

## 4. 標準の遊びは分かりやすく、LABでは大胆に試せる

通常の画面には、いま遊ぶために必要な操作を置きます。価格曲線、別ルール、画面構成、補助、演出などの比較はLABで行えます。LABは機能の置き場であると同時に、変更を具体的に遊び比べる場所です。

LABに存在することは、標準採用の決定ではありません。よい案は、何が良くなったかを説明し、標準ルール・セーブ・ランキングへの影響を整理してから提案してください。小さな修正や翻訳まで大きな企画書にする必要はありません。

実験設定でも表示だけのものと、結果の比較条件を変えるものがあります。「LABを開いたら全部ランキング対象外」「標準値に戻したら必ず対象に戻る」といった一括扱いはしません。具体的な判定は[LABとランキング](LAB.md)を確認してください。

## 5. 遊んだ時間と獲得した記録を守る

アップデート、再読込、PWAの更新、通常モードとチャレンジの切り替えで、進行が失われることは避けます。過去のクリアは、その時点のルール・目標・時間を持った記録です。新しいルールに合わせて過去の実績を書き換えません。

不具合調査でセーブを使うときは、まず新規プレイから作った再現用データを使います。既存プレイヤーにストレージ削除やPWAの削除を通常の解決手順として勧める前に、データを保持できる方法を検討してください。

## 6. 短いプレイと、戻ってこないことを区別する

10分で中断しても、あとで続きを楽しんでいるなら、短いプレイ自体が失敗とは限りません。改善では、再開のしやすさ、次の目標、短時間でも進歩を感じられるかを見ます。

統計を使うときは、次を区別します。

- ページを開いた記録、実際に操作した訪問、1つのゲーム進行、利用者の人数。
- 初めて来た直後の利用者と、再訪を確認できるだけの時間が経った利用者。
- 短い中断と、一定期間の再プレイが確認できないこと。
- 同じブラウザIDと同じ人。別ブラウザ・別URL・保存領域の削除では追跡が切れる場合があります。

計測を有効にしただけで、正確な離脱率が得られるわけではありません。比較には分母、観測期間、バージョン、除外条件を添えます。この文書は自動的な再訪率集計の実装を意味しません。

## 7. 自由に改造できる入口を保つ

友達も、初めて来た開発者も、人間も、Codexなどのコーディングエージェントも参加できます。オリジナルのコードや文書は[MIT](../LICENSE)で公開しています。forkして別のルールや見た目を試したり、自分の版として公開したりできます。第三者素材は[各素材の条件](../ASSETS.md)を引き継いでください。

本家への提案はIssueやPull Requestで共有します。公開リポジトリなので誰でも直接mainを書き換えられる、という意味ではありません。forkからの提案に、公式サービスの秘密情報や利用者データは不要です。

変更を説明するときは、**誰のどんな体験を良くするか、実際にどう変わるか、何を確認したか**を短く伝えてください。初めて触る人が次の一歩を選べるコードと文書を、一緒に保っていきます。

## English summary

Make small actions feel meaningful, keep shared-roll portfolio choices understandable, and use expressive feedback without sacrificing mobile responsiveness. Keep the default experience approachable and use LAB for explicit experiments. Protect saved progress and historical completion records. Evaluate short sessions separately from return behavior. Forks and focused pull requests are welcome; see [CONTRIBUTING](../CONTRIBUTING.md) and [AGENTS](../AGENTS.md).
