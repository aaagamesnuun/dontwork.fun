# プレイの進行・中断・再プレイを数える

計測はゲームの勝率・進行・保存を変更しません。結果公開後のイベントを使い、短時間プレイと再プレイ未確認を分けます。集計の単位は人ではなく、同じブラウザ内の匿名IDです。

## どのコードが何をするか

- `src/journey.ts`: 30分の非活動で訪問を区切る。ブラウザ保存領域で訪問IDを再読み込み間に共有する。
- `src/api.ts`: 既存イベントに schemaVersion 3 の `journey` 情報を追加する。輸送用の sessionId / sequence と訪問IDは別物。
- `src/App.tsx`: 新規セーブと続きからの起動、最初の案内画面、案内完了、前面での活動時間を通知する。
- `server/worker.js`: 従来の入力検証・匿名化・送信制限に加え、許可した訪問情報だけを取り込む。
- `server/funnel.js`: 受理済みの不変イベントから小さな訪問集計を更新し、認証された管理サイトに集計結果だけを返す。
- `drizzle/0010_funnel.sql`: 初回計測の目印と、訪問・ページ・ゲーム単位の集計テーブルを追加する。

同じ訪問でゲームをリセットしても訪問数は増えません。再読み込みした各ページの前面活動時間の最大値を合計します。同じページ内で複数のゲームを始めても、その累積時間を二重に足しません。送信済みイベントの再送・書き換えは、既存イベントの値から再集計するため加算されません。

## ファネルと再プレイ

主な導線は「訪問 → 実プレイ → スピン → ジャックポット → クリア」。最初に計測された訪問内で、この順序の到達を数えます。ジャックポットを経ないクリアは別の全クリア到達に含めます。WORK、次のギャンブルの初スピン、アップグレードは任意行動として別表示します。

最初の実プレイ開始から24時間・72時間・7日の観測幅を選びます。時間が経過していない記録は「観測待ち」とし、再プレイ率の分母から外します。別訪問で実プレイした場合だけ再プレイとします。ページを開いただけ、非表示中の進行だけでは実プレイの証拠になりません。別訪問の開始と前の訪問の最終活動の間に30分以上あることも確認します。

「時間内の再プレイ率」と「現時点まで再プレイが一度も未確認」は別の数字です。例えば初回から4日後に戻った人は、72時間以内の再プレイには含めませんが、現時点で1回だけのブラウザからは除きます。初回の前面活動が10分未満だった層も同じ方法で数えます。

初回の言語・端末・バージョン・モード・新規/既存セーブの分類を固定します。後のバージョン変更・言語変更・LABでの実プレイは再プレイに含めます。初回訪問でLABを使用したものは主要コホートから除きます。したがって「初回LAB除外」と「後のLAB再プレイを含む」は両立します。

前面活動時間は、実プレイが始まったページで、ゲームが動作中または直近2分に入力がある間の時間です。非表示中の進行と、操作しないまま開いたページの滞在時間を除きます。閉じる直前の未送信分、通信失敗、保存領域の削除、複数端末を完全には追跡できません。「未確認」は永久離脱や離脱原因の断定ではありません。

## 保存とアクセス

既存の生イベントは30日、ゲーム集計と訪問詳細は180日。匿名の初回計測時点だけは、古い訪問が期限切れになったブラウザを再び初回と数えないため、統計削除まで保持します。ゲームの統計削除は新しい2テーブルも削除します。名前・問い合わせ本文・IP・任意の自由文を新しい訪問集計には保存しません。

`GET /api/analytics/funnel` は `ANALYTICS_READ_TOKEN` に一致するBearer認証を必須とします。キー未設定時は閉じた状態になります。返すのは件数・割合・文章と集計条件で、プレイヤーIDやイベント本体は返しません。管理サイトは自身のサーバー側からこのAPIを呼び、キーをブラウザや公開リポジトリへ渡しません。管理サイトの閲覧権限は管理サイト側でも制限します。

フォークでは共有サービスを無効にした既定値を維持してください。自分のサービスを運用する場合だけ、自分のD1に追加マイグレーションを適用し、十分長いランダムキーをWorkerのsecretとして設定します。追加テーブル未適用時は既存イベントの保存を継続し、管理画面は準備待ちを表示します。追加テーブルへの集計は反映後に開始し、反映前のデータを自動でバックフィルしません。無料枠などによるデータベースの書き込み停止時には記録が欠けるため、ゼロ件を利用者ゼロと解釈しないでください。公式サービスのキー・匿名化キー・データベースを流用しないでください。既存の匿名化キーを変更すると、同じブラウザを継続して数えられなくなります。

## 検証

`src/journey.test.ts` と `server/funnel.test.js` で、再読み込み、30分境界、受理済みイベント再送、同時タブ、複数ゲームの時間重複、観測待ち、遅い再プレイ、言語変更、認証、削除、1万件超の集計を検証します。既存のテレメトリ・ゲームのテストも実行してください。

手動確認する場合は独立したローカル環境を使い、新規開始 → WORK → スピン → ジャックポット → 再読み込み → 30分後の再プレイ、統計オフ・削除を確認します。本番の検証用に架空のプレイヤー記録を作らないでください。
